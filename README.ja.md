[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 向けのソフトワークフロープラグインです：**キャンバス上でフローを設計し、1 つの計画プロンプトにコンパイルして、モデルに実行させます。**

エッジには**任意の条件**を付けられ、フローは逐次・並列・合流・条件分岐・ループ・ロールバックに対応します。プラグイン自体は実行エンジンを持たず、すべて現在のセッションのモデルが実行します。ステップ図として描ける作業なら何でも任せられます：複数ステップのコーディング作業、リサーチパイプライン、コンテンツ制作パイプラインなど。数百ステップのキャンバスでも、ドラッグやパンはフルフレームレートで動作します。

> [!TIP]
> **ワークフローパック**：[Minglink/dsh-workflows](https://github.com/Minglink/dsh-workflows) — すぐにインポートできる `.wflite.zip` ワークフローパック集です。「破甲制作」リサーチパイプラインが公開済みです（下記の [📋 利用可能なワークフロー](#-利用可能なワークフロー) を参照）。

> [!NOTE]
> **実験段階**：機能とデータ形式はまだ変更中で、どのリリースにも互換性のない変更が含まれる可能性があります。

## 📦 インストール

DeepSeek Harness 0.2.x の安定版で動作します。0.2.0 と 0.2.1 はプレビュー版（rc、beta）も含めてサポートしています。

| お使いの DeepSeek Harness | インストール |
|---|---|
| 0.2.0 / 0.2.1 安定版 | ✅ |
| 0.2.0 / 0.2.1 プレビュー版（rc、beta） | ✅ |
| 0.2.2 以降のプレビュー版 | 最新リリース時点でサポート。ブロックされる場合は次のプラグインリリースをお待ちください |
| 0.3 以降 | 未対応 |

> [!TIP]
> インストール後に **Workflow** タブが表示されない場合、DSH のバージョンが合っていない可能性が高いです。ホストはエラーを出さずにプラグインを**黙ってスキップ**します。上の表を確認し、Plugins ページでプラグインが有効になっていることを確かめてから DSH を再起動してください。それでも表示されない場合は、バージョン情報を添えて [issue を作成](https://github.com/Minglink/dsh-jailbreak-workflow/issues/new?template=bug_report.yml)してください。

### Web 版

Node.js 22 以降が必要です。

```bash
dsh plugin --profile web add @minglink/dsh-jailbreak-workflow
dsh web
```

### デスクトップ版

1. サイドバーの **Plugins** を開き、**Add plugin** → **Install a third-party plugin** をクリックします。
2. `@minglink/dsh-jailbreak-workflow` を入力し、**Install** をクリックします。
3. DeepSeek Harness を再起動します。

インストールが完了すると、セッションページの上部に **Workflow** タブが表示されます。

## 🚀 使い方

### モデルに頼む

会話の中でフローを一文で説明します。例：

> ワークフローを作って：コードを書いてからレビューし、レビューが不合格なら戻って修正する。最大 3 ラウンドまで。

モデルがワークフローを作成し、作成の過程がキャンバスに表示されます。内容に問題がなければ右上の **Run** をクリックするか、モデルに実行を頼んでください。

### 手で編集する

1. **Workflow** タブを開き、ワークフローを作成します。
2. 左側のライブラリからステップをキャンバスにドラッグし、プロンプトを入力して接続します。
3. 右上の **Run** をクリックするか、会話の中でモデルにワークフローの実行を頼みます。

### 進捗を追う

**Workflow settings** で **Record run state** をオンにします。以降は実行のたびに記録が残り、モデルの作業に合わせてキャンバスが更新されます。実行記録・ワークフロー・バージョンは、キャンバス左上から開く **Workflow hub** で管理できます。

## 🧩 機能

| 機能 | 説明 |
|---|---|
| 🎨 キャンバス編集 | ステップをドラッグして接続。合格 / 不合格の分岐やループに対応し、ワンクリックでレイアウトを整理 |
| 📎 リソース | ステップが読み書きするファイル、フォルダー、URL、Skill を添付 |
| 💬 実行前の質問 | 実行に必要な情報をユーザーから集め、回答を計画とともにモデルへ渡す |
| 🤖 モデルとの共同編集 | モデルがワークフローを直接作成・編集でき、キャンバスがリアルタイムに更新される |
| 📊 実行状態 | 進捗がリアルタイムでキャンバスに表示される。各ステップの要約を読み、状態を調整するとモデルに通知される |
| 🖥️ キャンバス表示（beta） | ダッシュボード、画像、ドキュメント、ログ、表、フォルダーをキャンバス上に直接表示し、実行中に更新。ループの各ラウンドを見直して比較できる |
| 👁️ ファイルプレビュー | 実行のリソースをその場で開ける：Markdown、HTML ページ（毎ラウンド更新するダッシュボードにしてループの出力を追える）、画像。フォルダーは 2 ペインで閲覧 |
| 🕘 バージョン | メモ付きでバージョンを保存し、差分を比較、いつでも切り戻し可能 |
| 📦 インポート / エクスポート | ワークフローと選んだバージョンを 1 つの `.wflite.zip` にまとめ、使用するファイルや Skill も同梱可能。インポート前に各項目の配置先を確認できる |
| 🧩 Skill としてエクスポート | 1 つのバージョンを skill（SKILL.md、ステップごとのタスク説明、同梱するファイルと Skill）にコンパイルし、プラグインなしで動作させる。zip でダウンロードするか、`~/.agents/skills` に直接インストール |
| 🧠 メモリー（beta） | うまくいった方法と落とし穴をワークフローが skill として保持し、次回の実行で従う。**Memory** ページで管理・バージョン管理でき、ワークフローパックと一緒にエクスポート可能 |
| 🏛️ Workflow hub | セッションをまたいだ実行記録、全ワークフローとそのバージョン、プラグイン設定を一か所に集約 |
| 🌗 インターフェース | ライト 4 種・ダーク 4 種のカラーテーマ。DSH のライト / ダークモードに追従。English / 中文 |

## 📁 パス変数

リソースのパスと出力ルートには 2 つの変数が使え、実行時に実際の場所へ置き換えられます：

| 変数 | 使える場所 | 置き換え先 |
|---|---|---|
| `{workflow}` | リソースのファイル・フォルダーパス（例：`{workflow}/refs/notes.md`） | ワークフロー専用のフォルダー（デフォルトは `~/.dsh/workflow-lite/assets/<ワークフロー名>/`）。どのワークスペースからも同じものを読み書きし、名前の変更やエクスポート時にはワークフローと一緒に移動する |
| `{instance}` | **Workflow settings** の **Output root**（デフォルトの `.workflow-lite/runs/{instance}/out` と同様） | この実行のインスタンス ID。実行ごとに出力が分かれる |

以前のバージョンで `{assets}/…` と書かれたパスも引き続き使え、ワークフローを開いたときに `{workflow}/…` に変換されます。

## 🧪 実験的機能

これらの機能は試行中で、動作やデータ形式が変わる可能性があります。ワークフローメモリーのほかに、上の機能表にある **キャンバス表示** も実験的機能です。

### ワークフローメモリー

うまくいった方法をワークフローが保持し、次回の実行で従えるようにする機能です。複雑なワークフローの高速化を狙っています。

- **使い方**：ステップ単位でオンにするか、ステップライブラリの **Basics** から **Memory** をキャンバスにドラッグして、ワークフロー全体で共有するメモリーとして追加します。追加時に既存のエントリーを選ぶか、新しく作成します。
- **内容**：エントリーは skill フォルダーで、冒頭の「Quick path」が次回そのタスクを最も低コストでこなす方法です。各ステップは学んだことを返信で報告し、ワークフロー終了時にモデルがそれを取り込みます。
- **管理**：Workflow hub の **Memory** ページでエントリーを閲覧・バージョン管理できます。エクスポート時に含めるかどうかを選べます。
- **制限**：同じメモリーを変更するインスタンスが同時に動いてもロックされないため、後から書き込んだ側が先の内容を上書きします。インストール済みのコピーに Skill を再エクスポートすると、蓄積されたメモリーが上書きされます。

メモリーはあくまで設定のショートカットです。より凝った仕組みが必要なら、リソースとプロンプトを組み合わせて自分で構築してください。

**効果があるかはまだ検証中で、フィードバックをお待ちしています。** 同じワークフローを繰り返した初期の試行では安定した高速化は見られませんでした。「Quick path」はその後に追加されたもので、効果があるかどうかは、より多くの実際のワークフローで確かめる必要があります。

## ❓ よくある質問

**インストール後に Workflow タブが表示されない**
[インストール](#-インストール)のトラブルシューティングのヒントを参照してください：まず DSH のバージョンを確認し、プラグインが有効になっていることを確かめてから DSH を再起動します。

**大きなワークフローは重くならない？**
なりません。大規模なキャンバス向けに専用のパフォーマンス改善を行っており、数百ステップのワークフローでもフルフレームレートでドラッグ・パンでき、約 0.5 秒で開きます。プロンプトや状態を編集してもキャンバス全体が再描画されることはありません。

**ステップはどのモデルが実行する？別の API キーは必要？**
プラグインは独自にモデルを呼び出さず、モデルの指定もありません：実行者は現在の DSH セッションで設定されているモデルです。Codex や Claude Code などのサブスクリプション型ツールを実行環境に組み込む方法を検討中です（[#3](https://github.com/Minglink/dsh-jailbreak-workflow/issues/3)）。

**ワークフローと出力はどこに保存される？**
ワークフローに付随するファイルはデフォルトで `~/.dsh/workflow-lite/assets/<ワークフロー名>/` に置かれ、名前の変更やエクスポート時に一緒に移動します。各実行の出力は設定された出力ルート（デフォルトは現在のワークスペースの `.workflow-lite/runs/<インスタンス ID>/out`）に保存されます。[パス変数](#-パス変数)を参照してください。

**dsh-workflows との関係は？**
このリポジトリはプラグイン（キャンバスとコンパイラー）で、[dsh-workflows](https://github.com/Minglink/dsh-workflows) は既製ワークフローのコレクションです。プラグインをインストールし、コレクションから `.wflite.zip` をダウンロードして Workflow hub からインポートしてください。

## ⚙️ 仕組み

1. **設計**：キャンバス上にステップを並べ、各実行者が受け取るプロンプトを書き、分岐やループでフローを表現します。
2. **コンパイル**：プラグインがワークフローを 1 つの計画プロンプトに変換します。作業の順序、ループ条件、各ステップの入力と出力が記述されます。
3. **実行**：モデルが計画の進め方（直接作業する、サブエージェントに振り分ける、チームを組む）を判断し、進捗をキャンバスに報告します。

プラグインは実行エンジンを持たず、追加のサービスも不要です。スケジューリングと判断は現在のセッションのモデルに任されています。
